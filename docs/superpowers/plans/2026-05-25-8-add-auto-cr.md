# Auto CR 自动评审功能开发 实现计划

> **Issue:** #8 | **链接:** https://code.alipay.com/antchain_efficiency/dtazzi_cline/issues/8
> **生成时间:** 2026-05-21
> **使用 issue-resolve 按计划逐 Task 实现**

**目标:** 在 Kanban runtime 内新增 Auto CR 能力：每 45 分钟扫描带 `PendingAGIReview` 标签的待合并 PR，按 Settings 中选中的 agent instance 直接启动对应评审任务。

**技术方案:** 复用现有 runtime config、workspace index、task start 链路和 `scheduled-task-executor` 模式，在 server 侧新增独立的 Auto CR scanner。Settings 只保存 `autoCrEnabled` 和 `autoCrAgentInstanceIds`，scanner 负责用 `antcode` CLI 扫描 PR、做 `(project, prIid, agentInstanceId)` 级别幂等判断、原子创建任务并立即启动。

**预估工作量:** 2-3 人天 / 中等偏复杂

## 手工 Sequential Thinking 结果

### Thought 1: 实现路径选择

选择在 runtime/server 内实现内置 scanner，而不是外部 cron。原因：

- 配置和执行在同一系统，最符合用户心智
- 可以直接复用已有 workspace index、runtime config 和 task start 逻辑
- 更容易做幂等与状态广播

### Thought 2: 文件结构设计

需要改动三块：

1. contract/config 层：新增 Auto CR 配置字段和返回值
2. Settings/UI 层：新增 Auto CR 设置区
3. server 层：新增 scanner + PR 查询 + 任务幂等/启动

### Thought 3: 接口与数据模型设计

新增 config 字段：

- `autoCrEnabled: boolean`
- `autoCrAgentInstanceIds: string[]`

建议新增 task metadata：

- `autoCrSource?: { projectName: string; prIid: number; prUrl: string; agentInstanceId: string }`

原因：只靠 prompt 字符串不适合做幂等判定。

### Thought 4: 依赖关系与任务排序

最优顺序：

1. 先补 contract/config，否则前后端都没有保存载体
2. 再做 Settings UI，方便手工联调
3. 再做 AntCode PR 查询 helper
4. 再做 scanner 和启动链路
5. 最后补测试与回归

### Thought 5: 测试策略

- contract/config：默认值、持久化、删除失效 instance
- UI：打开 Settings、勾选 Auto CR、保存 payload
- scanner：过滤、去重、局部失败、立即启动
- task/session：确保创建的 task 会把 instance 和 prompt 正确带入启动请求

### Thought 6: 关键决策点与潜在风险

关键决策已确认：

- prompt 固定 `评审下PR：PR URL`
- 标题固定 `[Auto CR][{AgentAlias}] Review PR !{iid} {title}`
- 命中后立即启动，不创建 backlog

剩余主要风险：

- 同一 PR 在多窗口 runtime 下重复创建
- agent instance 被删后，旧配置中的 ID 如何清洗
- task 启动失败时是否保留 review/in_progress/backlog 卡片

建议执行时采用保守策略：

- 先原子创建到 `in_progress`
- 若启动失败，回滚到 `backlog` 或清理该卡片，避免“幽灵运行中任务”
