# Spec: 报告内容结构 (FR2)

## 功能概述
生成的测试报告必须包含固定顺序的六大章节，内容标准化。

## 章节定义

### 1. 报告头
| 字段 | 来源 |
|------|------|
| 项目名 | `package.json` `name` 字段 |
| 生成时间 | 系统当前时间 ISO 8601 |
| 执行命令 | 实际使用的测试命令 |
| 框架/版本 | 检测到的框架名 + 版本号 |
| 执行环境 | Node.js 版本、OS 信息 |

### 2. 结果摘要
| 指标 | 说明 |
|------|------|
| 用例总数 | 所有用例计数 |
| 通过/失败/跳过数 | 各状态计数 |
| 通过率 | `通过数 / 总数 × 100%` |
| 总耗时 | 所有用例耗时之和 |
| 整体结论 | ✅ 全部通过 / ❌ 存在失败 |

### 3. 失败用例分析
- 仅当存在失败用例时渲染
- 每条包含：用例名、所属文件、错误信息、堆栈关键行（截断至 10 行）
- 敏感信息过滤：移除环境变量值、API key 模式匹配

### 4. 用例明细
- 按测试文件分组
- 每条显示用例名、状态图标、耗时
- 超过 200 条时截断并注明 "已截断，共 N 条用例"

### 5. 覆盖率
- 语句/分支/函数/行覆盖率百分比
- 低于 80% 的文件清单（标注具体值）
- 覆盖率不可用时标注 "未获取"

### 6. 附录
- 原始结果文件路径
- 生成工具名称与版本

## 验收标准
- 报告包含全部 6 个章节，顺序固定
- 失败用例章节含用例名、文件路径、错误信息
- 覆盖率缺失时标注 "未获取" 且其余章节正常
