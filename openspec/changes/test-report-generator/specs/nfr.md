# Spec: 非功能需求 (NFR)

## NFR1 性能
- 结果解析与报告生成（不含测试执行）应在 5 秒内完成（1000 用例规模）
- 实现：流式解析 + 增量构建，避免全量内存加载

## NFR2 健壮性
- 结果文件格式异常时降级输出，缺失字段标注 "未获取"
- 不得崩溃或静默丢弃数据
- 实现：每个解析步骤包裹 try-catch，异常时记录到诊断日志

## NFR3 安全
- 报告中不得泄露环境变量、密钥类内容
- 错误堆栈须过滤敏感路径外的凭据信息
- 实现：正则匹配过滤 `KEY=value`、`token:`、`secret:` 等模式

## NFR4 幂等性
- 同一结果文件多次生成报告，内容一致（时间戳字段除外）
- 实现：报告内容基于结果数据确定性渲染，不依赖外部状态

## NFR5 可维护性
- 框架解析器采用插件式结构，新增框架支持不影响既有解析器
- 实现：`TestResultParser` 接口 + `ParserRegistry` 注册机制

## 验收标准
- 1000 用例解析 + 报告生成 < 5s
- 损坏的 XML 文件返回明确错误，不崩溃
- 堆栈中包含 `TOKEN=xxx` 时自动过滤
- 新增解析器无需修改现有代码
