# Spec: 用户场景 (US1-US4)

## US1：本地开发完成后生成报告
**场景**：开发者说"帮我跑测试并生成报告"
**验收**：报告落盘且路径明确

## US2：失败用例分析
**场景**：测试有失败用例时，报告直接给出失败原因摘要与相关文件定位
**验收**：失败用例含错误信息、堆栈摘要、源文件路径

## US3：质量状态同步
**场景**：QA/测试负责人需要向团队同步质量状态
**验收**：摘要板块含通过率、覆盖率等可量化指标

## US4：CI 解析模式
**场景**：CI 维护者将已有 JUnit XML / JSON 结果转成报告，不重复跑测试
**验收**：指定 `result_file` 后跳过执行，直接解析并生成报告
