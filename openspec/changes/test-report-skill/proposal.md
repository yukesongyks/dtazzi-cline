# Proposal: test-report-skill

## Summary
提供一个 Agent Skill，使 Agent 在执行测试后能够自动解析测试结果并生成结构化、可读性强的标准测试报告（Markdown 格式）。

## Motivation
当前团队在完成测试执行后，测试结果散落在终端输出、CI 日志或框架原生产物（如 JUnit XML、coverage 目录）中，存在以下痛点：
- 测试结果需要人工收集、整理、汇总，耗时且易遗漏
- 缺乏统一格式的测试报告，跨项目/跨团队沟通成本高
- 失败用例的上下文（错误信息、堆栈、关联代码）需要人工回溯
- 覆盖率、通过率等质量指标无法沉淀为可追踪的历史数据

## Scope

### In Scope
- **G1**: 一条指令自动完成：执行测试 → 收集结果 → 生成报告
- **G2**: 报告内容标准化，包含摘要、明细、失败分析、覆盖率四大板块
- **G3**: 支持主流测试框架的结果解析（Jest/Vitest JSON、pytest JUnit XML/JSON、通用 JUnit XML）
- **G4**: 报告支持多种输出格式，默认 Markdown
- 执行模式与解析模式双模式支持
- 插件式解析器架构（NFR5）

### Out of Scope (本期不做)
- 测试用例的自动生成或修复
- 报告的在线托管 / Web 服务化展示
- 多次运行结果的趋势对比分析
- 非测试类质量报告（如 lint、安全扫描）的聚合
- HTML 输出、JSON 伴随产物（P1，后续里程碑）
- 自动推送到 IM / 邮件等渠道

## Affected Areas

## User Stories
| 编号 | 角色 | 场景 | 验收要点 |
|------|------|------|----------|
| US1 | 开发者 | 本地开发完成后说"帮我跑测试并生成报告"，得到 Markdown 报告 | 报告落盘且路径明确 |
| US2 | 开发者 | 测试有失败用例时，报告直接给出失败原因摘要与相关文件定位 | 失败用例含错误信息、堆栈摘要、源文件路径 |
| US3 | QA/测试负责人 | 需要向团队同步质量状态，要求报告含通过率、覆盖率等核心指标 | 摘要板块含可量化指标 |
| US4 | CI 维护者 | 在 CI 流程中复用该 Skill，将已有 JUnit XML/JSON 结果转成报告，不重复跑测试 | 支持"仅解析已有结果"模式 |

## Risks
- **R1**: 各框架 reporter 输出差异大，解析层需要良好抽象 → 通过 NFR5 插件式设计缓解
- **R2**: 测试执行耗时不可控，长任务需交由后台执行并轮询 → 依赖 Agent 运行时的后台任务能力
- **R3**: 环境变量/密钥可能通过错误堆栈泄露到报告中 → 通过 NFR3 安全过滤机制应对

## Open Questions
- **Q1**: 首期目标项目栈是否以 TypeScript/Node 为主？→ 假设：是，按此制定 P0 范围
- **Q2**: 报告是否需要中文/英文双语模板，还是仅中文？→ 假设：仅中文，后续可扩展
- **Q3**: 是否需要将报告自动推送到 IM/邮件等渠道？→ 当前列为非目标

## Rollout
- 作为独立 Skill 发布，不影响现有功能
- 回滚：删除 skill 目录即可，无数据库迁移或 API 变更
