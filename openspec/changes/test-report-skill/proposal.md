# Proposal: test-report-skill

## Summary

为 Kanban Agent 平台新增一个 **test-report** Skill，使 Agent 能够在测试执行后自动解析测试结果，生成结构化、可读性强的标准测试报告（Markdown/HTML/JSON），覆盖摘要、明细、失败分析、覆盖率四大板块。

## Motivation

当前团队在完成测试执行后，测试结果散落在终端输出、CI 日志或框架原生产物中：

- 测试结果需要人工收集、整理、汇总，耗时且易遗漏
- 缺乏统一格式的测试报告，跨项目/跨团队沟通成本高
- 失败用例的上下文（错误信息、堆栈、关联代码）需要人工回溯
- 覆盖率、通过率等质量指标无法沉淀为可追踪的历史数据

## Goals

| ID  | 目标                                                              |
| --- | ----------------------------------------------------------------- |
| G1  | 一条指令即可自动完成：执行测试 → 收集结果 → 生成报告               |
| G2  | 报告内容标准化，包含摘要、明细、失败分析、覆盖率四大板块            |
| G3  | 支持主流测试框架的结果解析（Jest、Vitest、pytest、JUnit XML）       |
| G4  | 报告支持多种输出格式，默认 Markdown                                |

## Non-Goals

- 不做测试用例的自动生成或修复（仅报告）
- 不做报告的在线托管 / Web 服务化展示
- 不做多次运行结果的趋势对比分析（列为后续迭代候选）
- 不做非测试类质量报告（如 lint、安全扫描）的聚合

## User Stories

| 编号 | 角色             | 场景描述                                                                 | 验收要点                                                 |
| ---- | ---------------- | ------------------------------------------------------------------------ | -------------------------------------------------------- |
| US1  | 开发者           | 本地开发完成后说"帮我跑测试并生成报告"，得到一份 Markdown 报告            | 报告落盘且路径明确                                       |
| US2  | 开发者           | 测试有失败用例时，希望报告直接给出失败原因摘要与相关文件定位              | 失败用例含错误信息、堆栈摘要、源文件路径                  |
| US3  | QA / 测试负责人  | 需要向团队同步质量状态，要求报告含通过率、覆盖率等核心指标                | 摘要板块含可量化指标                                     |
| US4  | CI 维护者        | 在 CI 流程中复用该 Skill，将已有 JUnit XML / JSON 结果转成报告，不重复跑测试 | 支持"仅解析已有结果"模式                                 |

## Out of Scope

- 测试用例自动生成与修复
- 报告在线托管 / Web 服务化
- 历史趋势对比分析
- lint / 安全扫描等非测试类质量报告聚合
- 自动推送报告到 IM / 邮件等渠道

## Risks & Mitigations

| 风险                                          | 缓解措施                                   |
| --------------------------------------------- | ------------------------------------------ |
| 各框架 reporter 输出差异大，解析层复杂度高    | 插件式解析器架构（NFR5），新增框架不影响既存 |
| 测试执行耗时不可控，长任务可能阻塞 Agent      | 委托后台执行 + 轮询机制                     |
| 结果文件格式异常/字段缺失导致崩溃             | 降级输出（缺失项标注"未获取"），不崩溃       |

## Open Questions

| ID  | 问题                                                               | 当前假设                     |
| --- | ------------------------------------------------------------------ | ---------------------------- |
| Q1  | 首期目标项目栈是否以 TypeScript/Node 为主？                         | 是，按此制定 P0 范围         |
| Q2  | 报告是否需要中文/英文双语模板，还是仅中文？                         | 仅中文，模板内置中文标签     |
| Q3  | 是否需要将报告自动推送到 IM / 邮件等渠道？                         | 不需要，列为非目标           |

## Dependencies

- 无外部系统依赖
- 依赖 Kanban Agent 的 Skill 运行时（`exec`、`write`、文件系统访问）
- 依赖项目内已安装的测试框架（Jest / Vitest / pytest）

## Related Changes

无（新增 Skill，不影响现有功能）
