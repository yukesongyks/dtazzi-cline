# Spec: 报告内容结构

**Capability**: test-report-skill / report-content
**Covers**: FR2

## Overview

定义生成的测试报告必须包含的标准章节结构、各章节内容规范及数据呈现规则。

## Report Structure (固定顺序)

### 1. 报告头

| 字段              | 来源                     | 说明                     |
| ----------------- | ------------------------ | ------------------------ |
| 项目名            | `package.json` / `pyproject.toml` / 目录名 | 项目标识     |
| 生成时间          | 系统时间                 | ISO 8601 格式            |
| 执行命令          | 实际执行的测试命令       | 完整命令字符串           |
| 框架/版本         | 自动检测结果             | 如 `Jest 29.7.0`         |
| 执行环境摘要      | `os` + `node`/`python` 版本 | 运行环境信息          |

### 2. 结果摘要

| 字段       | 格式            | 说明                                |
| ---------- | --------------- | ----------------------------------- |
| 用例总数   | 整数            |                                     |
| 通过数     | 整数            |                                     |
| 失败数     | 整数            |                                     |
| 跳过数     | 整数            |                                     |
| 通过率     | 百分比 (xx.x%)  | `passed / total * 100`              |
| 总耗时     | 人类可读格式    | 如 `12.3s`，来源为框架报告耗时      |
| 整体结论   | ✅ 或 ❌         | 所有用例通过为 ✅，否则为 ❌         |

**fail_threshold 规则**：若配置了 `fail_threshold`（如 80），通过率低于该值时，结论标记为"不达标"。

### 3. 失败用例分析（有失败时必选）

每条失败用例包含：

| 字段       | 说明                                     |
| ---------- | ---------------------------------------- |
| 用例名     | 完整测试用例名（describe/it 全路径）     |
| 所属文件   | 源文件相对路径                           |
| 错误信息   | 框架返回的错误消息                       |
| 堆栈关键行 | 截断至最多 20 行，过滤 node_modules 等   |

**排序规则**：按所属文件分组，同文件内按用例名排序。

### 4. 用例明细

- 按测试文件分组展示
- 每条用例包含：用例名、耗时（ms）、状态（✅/❌/⏭️）
- 默认展示全部用例
- 超过 200 条时截断，并注明 "已截断，共 N 条用例，仅展示前 200 条"
- 支持 Markdown `<details>` 折叠

### 5. 覆盖率（若可获取）

| 指标       | 说明                       |
| ---------- | -------------------------- |
| 语句覆盖率 | Statements: xx.x%          |
| 分支覆盖率 | Branches: xx.x%            |
| 函数覆盖率 | Functions: xx.x%           |
| 行覆盖率   | Lines: xx.x%               |

附加：低于 80% 阈值的文件清单（文件名 + 覆盖率数值）。

覆盖率不可用时：整个章节标注 **"未获取"**。

### 6. 附录

| 字段           | 说明                     |
| -------------- | ------------------------ |
| 原始结果文件路径 | 解析模式下的输入文件路径 |
| 生成工具版本   | Skill 版本号             |

## Acceptance Criteria

- **AC-FR2-1**: 在含 Jest 的 TS 项目中生成报告，产出符合上述 6 章节结构，摘要数据与 Jest 原始 JSON 输出一致
- **AC-FR2-2**: 存在失败用例时，失败分析章节包含用例名、文件路径、错误信息
- **AC-FR2-3**: 覆盖率数据存在时正确呈现语句/分支/函数/行覆盖率
- **AC-FR2-4**: 覆盖率数据不存在时，覆盖率章节标注"未获取"且其余章节正常
- **AC-FR2-5**: 用例超过 200 条时截断并注明总数

## Edge Cases

- 全部用例通过时，失败分析章节显示"无失败用例"
- 全部用例跳过时，摘要结论为 ⏭️ 并附说明
- 用例数为 0 时，报告标注"未检测到用例"
- 多个测试文件时，明细按文件名字母序排列
